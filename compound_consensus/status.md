## 這支在做什麼（一段話）

使用者挑出**同一個標本**的多個 `.mea`（重複測量），本應用把每個檔的化合物候選彙整
起來，依「有幾個重複支持」排序。**這是 VOCal 與第一支應用都不做的一步**——反編譯
VOCal 0.4.31.412（461 個混淆類別 + 7 個外掛）確認：它的 `Compounds` 每一筆只綁一個
`.mea`（實測 0/28 參照超過一個檔），化合物身分是操作者逐檔手動標的。

## 隔離規則（改動前必讀）

1. **不修改任何既有 `.py`**。既有模組一律 import 後呼叫。
2. **不寫前兩支的產物**：峰的選取寫 `_peaks_state3.json`（不是 `_peaks_state.json`），
   指紋寫 `_peaks2_fp3.json`，自己畫的背景圖帶 `_c3`。**讀**它們的產物是允許的。
3. **不寫任何東西進 `GAS/`**：`use_sidecar=False`，`.mea` / `.gasprj` 唯讀。
4. **不用 subprocess**。第一支用 `[sys.executable, "peaks.py", ...]` 起子行程，那在
   打包成 exe 之後會變成用 exe 再開一次 GUI（`sys.executable` 是 exe，而 `peaks.py`
   不在磁碟上）。第二支已經改掉，本應用跟隨。

## 1.0 開發期間修掉的問題（症狀與原因差很遠的那些）

| 症狀 | 真正的原因 |
|---|---|
| 熱圖上**一個圈都沒有**，也沒有錯誤 | 背景圖 y 軸是 RI，而 `detect_one()` 只找峰不掛 RI → 28 顆峰全部 `ri=None` → 算不出座標 |
| 視窗只剩一條工具列 | `quit_app` 被插進 `_build()` 中間，建三個面板的程式碼變成 `destroy()` 之後的無法到達碼。**語法正確、import 成功** |
| 按「掃描」時整個視窗縮成一小塊 | 狀態列每個檔換一次文字，pack 把寬度變化傳到最上層；面板還空著時自然大小很小 |
| 掃描完 UI 凍住十幾秒 | 相似度在主執行緒算（`_drain()` 裡） |
| 相似度整欄「不在掃描範圍」 | 掃描只掃已勾選的那一組——但相似度是拿來**決定**分組的，循環論證 |
| 兩個檔的相似度永遠 −1.00 | 逐區域標準化在 n=2 時把每欄壓成 (+1,−1)，相關係數與資料無關 |
| 改了 `top_n` 表格變了、熱圖沒變 | 圈看 `active`，而 `mark_rules()` 寫 `rule_active`，兩個鍵沒接起來；**共識也照樣算進那些峰** |
| 預告 8 分鐘、實際跑 16 分鐘 | 估時看 `_maxima.npz`（第一支的快取），而偵測認的是 `_peaks2.json` |
| `--dry-run` 竟然會寫檔 | 採信既有快取會補寫指紋，而 `plan()` 在 dry run 時也跑 |
| 選 `GAS/` 得到 0 個樣品 | 它底下只有子資料夾。**第二支踩過同一個坑** |

> **工具面的坑**：用 heredoc 寫含 `\n` 的 Python 字串，跳脫會被吃掉變成真的換行，
> 產生 `SyntaxError`。這一輪踩了三次。含跳脫字元的檔案編輯改用編輯工具，不要用 heredoc。

## 鑑定能力的硬上限（**接手前一定要知道**）

漂移庫（`.iml`）只涵蓋 **84 個化合物**，而 RI 庫（`.ril`）有 9,958 個。2D 命中需要
兩軸都對上，所以**RI 庫裡 97% 的化合物永遠拿不到 2D 命中**，RI 再準也沒用。

另有 213 個化合物的漂移資料**存在但沒有宣告 `DtMode`**，實測與已宣告的來源
**51/55（93%）吻合在 ±0.05 內**（中位差 0.0028）。接受它們會讓涵蓋變成 297 個（×3.5）。

**使用者 2026-08-31 決定：`library.py` 與 `library_data/` 一律不得修改**，所以這條
路關閉。完整數字與推導在 `README.md`。**這是考慮過並否決的方案，不是還沒發現的改進。**

因此本應用的目標是**一份誠實排序的候選短名單**，不是一個名字。

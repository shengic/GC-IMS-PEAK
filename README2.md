# GC-IMS 區域矩陣 — 第二支應用

**Version: 1.0 — by Albert Sheng**

> 第二支應用有**自己的版本序列**，從 1.0 起算，與第一支應用（`main.py`，現為 3.x）
> 無關。兩者各自獨立演進，共用的只有底層模組。第一支應用的說明見 `README.md`。

一次分析**一整批** `.mea`：在所有檔案上量同一組區域，產出「**區域 × 檔案**」的強度
矩陣，用來比較實驗分組。

---

## 兩支應用的差別

| | 第一支（`main.py`） | 第二支（`main2.py`） |
|---|---|---|
| 一次處理 | 1 個 `.mea` | 一整批（實測 15–18 個） |
| 峰怎麼來 | 每個檔案各自偵測 | **同一組座標**套用到每個檔案 |
| 輸出 | 該檔的峰清單 + 候選化合物 | **區域 × 檔案的強度矩陣** |
| 用途 | 看清楚單一樣品 | 比較 A/B/C/D/E 組 |

**為什麼要「同一組座標」**：各檔獨立找出來的峰清單彼此對不齊——A 樣品的第 12 顆峰
和 B 樣品的第 12 顆峰未必是同一個化合物。要比較分組，必須在**相同位置**上量每一個
樣品。這也是為什麼矩陣裡**沒偵測到峰的格子照樣要有值**：「這個樣品在這個位置沒有
東西」本身就是一項資訊，缺值則不是。

這個模型不是憑空設計的，是拆解 VOCal 的 `.gasprj` 後照著做的——詳見
`Area_Matrix2.md` 第 1 節。

## 快速開始

```bash
python main2.py
```

1. **1. Browse batch folder** → 選**含 `.mea` 的資料夾**
   ⚠ 對話框預設開在 `GAS/`，但 `GAS/` 底下只有子資料夾、沒有 `.mea`。選到它會提示並
   列出該去哪個子資料夾（例如 `GAS/Coffee-bean`）。
2. 想先快速試跑：把 **files** 設成 `2`
3. **2. Run batch** → 左側檔案清單會即時上色，右下 **Progress log** 顯示所有訊息
4. 跑完矩陣就出現，並自動寫入 `results/`

### 命令列

```bash
python areas2.py "GAS/Coffee-bean"                    # 共識區域（自動找峰）
python areas2.py "GAS/Coffee-bean" \
    --from-gasprj "GAS/Coffee-bean/rawbean-20260625.gasprj" --skip-detect
```

## 介面

| 控制項 | 作用 |
|---|---|
| **files: all / 1 / 2 / 5** | 只跑前 N 個檔案。**第一次先用 2**。 |
| **Stop** | 目前檔案跑完後停下。 |
| **view: summary / all files** | 摘要（預設）＝每個實驗組一欄；all files ＝逐檔一欄。 |
| **Baseline (AsLS)** | 扣掉隨溫度上升的傾斜基線；體積積分需要它（每檔 +16 秒）。 |
| **metric** | 每格顯示什麼：`volume` 總和（定量）· `max` 峰高 · `mean` 平均。三個都會算，切換不重算。 |
| **Compare with .gasprj areas** | **預設關閉。** 改用 VOCal 畫好的方框，僅供對照驗證。 |
| **Fast: skip peak detection** | 跳過找峰，快約 50 倍。只在勾了上一項時可用。 |
| **Export CSV** | 另存目前 metric 的矩陣。 |

**檔案清單顏色**：琥珀＝偵測中（慢）· 淡藍＝已偵測 · 橘＝量測中 · 綠＝完成。
**雙擊矩陣任一列** → 該區域的座標、命名與**逐檔完整數值**。

## 怎麼讀矩陣

```
 #  name              RI     drift   rt_s  n_det  A(n=3)   B(n=3)   C(n=3) …
 1  butyl acetate-M  1077.3  1.240  593.2    3    7.2e+05  5.8e+04  7.2e+04
 3  area 6           1127.5  1.146  689.2    3    1.1e+05  5.8e+04  …
```

- **淺綠底** ＝ 這個區域比對到了化合物；其餘是 `area N`——**沒有名字照樣量**，
  這是刻意模仿 VOCal（它 57 個區域也只有 27 個有名字）。命名是註記，不是量測的前提。
- **`n_det`** ＝ 有幾個檔案在那裡**真的偵測到峰**。與「有沒有量到值」是兩回事：
  每一格都有值，`n_det` 告訴你其中幾格底下有偵測到的峰。`—` 代表用了 Fast 模式
  （沒去找峰），**不是 0**。
- **空白格** ＝ 沒量到（方框落在該檔範圍外），**不是 0**。「沒量到」與「量到零」在
  比較分組時意義完全不同。

## 速度

實測單檔耗時（20414 × 3150 的真實資料）：

| 步驟 | 秒 | 佔比 |
|---|---|---|
| 找峰（union-find，在 `peaks.py`） | 55.4 | **75%** |
| AsLS 基線 | 16.8 | 23% |
| 其餘 | 1.8 | 2% |

找峰佔了四分之三，而**方框若來自 `.gasprj`，找峰只用來填 `n_det`**——可以整段跳過。

| 你要什麼 | 設定 | 15 檔 |
|---|---|---|
| 先看到矩陣 | `.gasprj` + Fast + 不扣基線 | **~12 秒**（實測） |
| 要定量的體積 | `.gasprj` + Fast + 扣基線 | ~5 分鐘 |
| 用自己的區域 | 共識 + 扣基線 | ~18 分鐘（僅首次，之後走快取） |

## 產物

```
results/<base>_peaks2.json          逐檔找峰結果 + 參數
results/<folder>_areas2.json        區域定義 + 完整 provenance
```

矩陣，內容與哪支寫的無關）。扣過基線的資料**絕不寫回** `.npz`——否則 `main.py` 會把
它當原始值載入而毫無跡象。細節見 `Area_Matrix2.md` 第 2 節。

## 已知限制

- **沒有跨檔保留時間對齊**：靠方框夠寬吸收漂移，與 VOCal 手畫寬框同樣作法。
- **`volume` 不是嚴謹的峰體積積分**：方框內高於 floor 的簡單加總，沒有峰形擬合。
- **K0 沒有用在區域命名上**：K0 需要逐峰 `dt_index`，區域層級沒有單一值。
- RI 的既有疑慮（管柱極性，見第一支應用的 `ketone_RI_provenance.md`）原樣傳遞到本
  應用的 provenance，不會因為換一支應用就消失。
